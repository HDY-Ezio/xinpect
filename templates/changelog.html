🔧 引擎架构修复：Bundle规则执行通道打通

此前B8/B9/B10三大规则引擎虽然已加载11,380条规则，但扫描流程中未实际调用执行。v6.2修复了E2引擎的scan()函数，将 scan_bundle_security() 正式接入扫描链路。现在每一条规则都会真正参与代码扫描。

📋 规则格式标准化

所有11,380条规则统一为8字段标准结构：

id / language / severity / title / description / pattern / fix / applicable_files

支持按引擎号、语言、严重级别快速检索，如 grep "E2-SEC" 精确筛选安全规则。

v6.0 2026-10-12

🛡️ 业务逻辑安全检测（核心升级）

传统 SAST 工具能发现 SQL 注入、XSS 这类技术漏洞，但对业务逻辑漏洞基本无解：

  • 用户 A 能不能访问用户 B 的订单？
  • 支付金额能不能被前端篡改？
  • 同一个订单能不能重复支付？
  • 退出登录后 Session 真的失效了吗？

v6.0 的 E2 安全检测引擎新增 50+ 条业务逻辑安全规则，覆盖 7 大维度：

密码安全8条弱密码策略、明文存储、弱哈希算法
认证授权10条越权访问、JWT 误用、RBAC 缺陷
输入验证8条业务层输入校验缺失、类型绕过
会话安全6条Session 固定、会话劫持、并发限制
支付安全8条金额篡改、重复支付、退款漏洞
数据安全6条敏感数据泄露、数据完整性破坏
审计日志4条关键操作审计缺失、日志注入
其他变更
  • 引擎架构统一为 E1-E7 + AI语义分析 + PoC验证，命名更清晰
  • 检测规则总数从 2400+ 提升至 2500+
  • 新增 Agent 安全检测和高级业务逻辑检测
