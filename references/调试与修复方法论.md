# 调试与修复方法论手册

> 内化自：bug-fixing v4.0 / superpowers-systematic-debugging / debug-pro / log-analyzer
> 用途：QA检测出问题后，指导系统化定位与修复，确保零回归

---

## 一、零回归修复流程（bug-fixing v4.0 核心）

### 12条铁律（绝不违反）

| # | 铁律 | 说明 |
|---|------|------|
| 1 | 根因必须通过4重验证 | 可复现 + 因果关系 + 可回退 + 机制清晰 |
| 2 | 修复前必须过5重范围检查 | 调用方 + 接口契约 + 不变量 + 调用点 + 重复代码扫描 |
| 3 | 必须追踪影响链 | 代码→数据→时间→事件，全文件扫描同类问题 |
| 4 | 必须预测副作用 | 修改前检查盲点清单 |
| 5 | 修复后必须回归验证 | 功能 + 性能 + 并发 + 所有影响层级 |
| 6 | 必须验证运行时加载 | 清缓存 + 重启 + 走一遍代码路径 |
| 7 | 框架行为读源码确认 | 不信文档/注释/假设 |
| 8 | UI问题必须有运行时证据 | 截图 + DevTools + 复现步骤 |
| 9 | 修复完成=Bug摘要+代码审查+知识沉淀+自我反思 | 四件套缺一不可 |
| 10 | 修复前先分层定位 | 代码bug？配置错？架构问题？AI能力边界？在根因层修，不在症状层修 |
| 11 | 模式匹配必须检查边界条件 | 正则/字符串/名称查找都要加边界 |
| 12 | 修复前先搜历史bug库 | 已知模式直接复用方案 |

### 6阶段修复流程

```
Phase 0: 分诊 → 严重度(P0-P3) + 复杂度(简单/标准/复杂)
Phase 1: 复现 → 证据收集
Phase 2: 根因分析 → 假设阶梯 + 5Whys + 影响链
Phase 3: 范围+预测 → 5重范围检查 + 副作用预测
Phase 4: 修复 → 最小改动原则
Phase 5: 验证+审查 → 回归测试 + 运行时验证 + Bug摘要
Phase 6: 知识沉淀 + 自我反思
```

### 严重度分级（控制流程深度）

| 级别 | 标准 | 流程深度 |
|------|------|---------|
| P0 致命 | 生产挂了 / 数据丢失 / 安全漏洞 | 全流程 |
| P1 高 | 核心功能坏了 / 数据损坏 | 全流程 |
| P2 中 | 非核心功能 / UI问题 | 标准流程（跳过策略对比） |
| P3 低 | 表面问题 / 边缘case | 快速修复 |

### 根因确认4重门（Rule 1）

根因确认必须**全部满足**：
1. **可复现**：可控场景下能稳定触发
2. **因果性**：最小改动让bug消失
3. **可回退**：还原改动bug又出现
4. **机制清晰**：能指出具体代码路径/状态转换

## 二、四阶段调试法（superpowers 核心）

### 核心原则
> 随机修bug = 浪费时间 + 制造新bug
> 症状修复 = 失败

### 四阶段

| 阶段 | 关键活动 | 成功标准 |
|------|---------|---------|
| **1. 根因调查** | 读错误、复现、查变更、追数据流 | 理解了是什么和为什么 |
| **2. 模式分析** | 找正常工作的例子、对比差异、理解依赖 | 识别出差异点 |
| **3. 假设与测试** | 形成理论、最小化测试、逐个验证 | 确认或排除假设 |
| **4. 实现修复** | 写失败用例、实现单一修复、验证 | Bug解决，测试通过 |

### 红旗警告（出现就立刻停，回到阶段1）

- 「先快速修复，以后再调查」
- 「就试试改X看看行不行」
- 「一次加好几个改动一起跑」
- 「跳过测试，我手动验证过了」
- 「已经试了2+次修复了」
- 「每次修复都在不同地方暴露新问题」

### 3次修复失败 → 质疑架构

**架构问题信号：**
- 每次修复都在不同地方揭示新的共享状态/耦合
- 修复需要"大规模重构"才能实现
- 每个修复都在其他地方产生新症状

**动作：** 停止修bug，和老板讨论架构重构。

## 三、7步调试协议（debug-pro）

1. **复现** — 稳定复现，记录精确步骤、输入、环境
2. **隔离** — 缩小范围，二分法，用git bisect查最近变更
3. **假设** — 形成具体的、可验证的根因理论
4. **埋点** — 加针对性日志、断点、断言
5. **验证** — 确认根因，不对就回到第3步
6. **修复** — 最小正确改动，抵制顺手重构的冲动
7. **回归测试** — 写测试用例盖住这个bug，验证通过

## 四、日志分析速查手册（log-analyzer）

### 基础错误搜索

```bash
# 所有错误
grep -i 'error\|exception\|fatal\|panic\|fail' app.log

# 错误+3行上下文
grep -i -C 3 'error\|exception' app.log

# 按错误类型统计
grep -oP '(?:Error|Exception): \K[^\n]+' app.log | sort | uniq -c | sort -rn | head -20

# HTTP 5xx错误
awk '$9 >= 500' access.log
```

### 按时间过滤

```bash
# 最近1小时的错误
HOUR_AGO=$(date -u -d '1 hour ago' '+%Y-%m-%dT%H:%M')
awk -v t="$HOUR_AGO" '$0 ~ /^[0-9]{4}-[0-9]{2}-[0-9]{2}T/ && $1 >= t' app.log | grep -i 'error'

# 两个时间点之间
awk '$0 >= "2026-02-03T10:00" && $0 <= "2026-02-03T11:00"' app.log
```

### JSON结构化日志（jq）

```bash
# 按级别过滤
cat app.log | jq 'select(.level == "error")'

# 提取关键字段
cat app.log | jq -r '[.timestamp, .level, .message] | @tsv'

# 按级别统计
cat app.log | jq -r '.level' | sort | uniq -c | sort -rn

# 按消息分组统计错误
cat app.log | jq -r 'select(.level == "error") | .message' | sort | uniq -c | sort -rn
```

### 关联ID追踪

```bash
# 单个请求全链路
grep 'req-abc123' app.log

# 跨文件追踪
grep -rH 'correlation-id-xyz' /var/log/service-a/ /var/log/service-b/
```

### 堆栈跟踪分析

```bash
# 提取所有堆栈跟踪
grep -A 20 'Traceback\|Exception in thread\|at .*\.java' app.log

# 堆栈频率统计（找最常出现的崩溃点）
grep 'File.*line' app.log | sort | uniq -c | sort -rn | head -10
```

## 五、QA检测→修复闭环（整合方案）

```
QA检测出问题
    ↓
Phase 0 分诊：按严重度分级
    ↓
P3/简单 → 快速修复 → 验证 → 关闭
    ↓
P1-P2/标准 → 四阶段调试 → 零回归修复流程 → Bug摘要
    ↓
P0/复杂 → 全流程 + 影响链追踪 + 架构审视
    ↓
知识沉淀：bug-records.md 记录每次修复
```

### QA报告补充模板

当QA检测出问题时，除了问题描述，还应给出：

```markdown
## 修复建议
- **问题层级**：代码bug / 配置问题 / 架构设计 / AI能力边界
- **建议修复优先级**：P0 / P1 / P2 / P3
- **可能影响范围**：单文件 / 单模块 / 跨模块 / 全系统
- **参考修复模式**：[对应bug-patterns里的模式名]
- **验证建议**：需要跑哪些测试或检查项
```

## 六、常见问题分层速查表

| 问题类型 | 优先排查方向 | 工具/方法 |
|---------|-------------|----------|
| 后端报错 | 堆栈跟踪 → 请求参数 → 最近变更 | 日志分析 + git diff |
| 前端UI异常 | 先拿运行时证据 → 控制台 → DOM → state | 截图 + DevTools + 复现步骤 |
| 性能问题 | 先测基线 → 找热点 → 定位瓶颈 | profiler + 计时埋点 |
| 偶发问题 | 找时间规律 → 并发条件 → 环境差异 | 压测 + 日志关联 |
| 数据异常 | 追溯写入路径 → 事务边界 → 并发竞争 | 审计日志 + 数据库binlog |
| 集成问题 | 接口契约 → 序列化 → 超时重试 | API日志 + 契约测试 |
| AI/LLM异常 | 工具绑定模式 → 流式输出 → token限制 → prompt注入 | 完整交互日志 + 版本对比 |
