# 快速自检清单（手动模式）

> 适合上线前快速把关、代码提交前自查。对着清单逐项过，3分钟出结论。

## 评分标准

| 分数 | 等级 | 上线建议 |
|------|------|---------|
| 90-100 | 优秀 | ✅ 可直接上线 |
| 70-89 | 良好 | ✅ 修完阻断项上线 |
| 50-69 | 一般 | ⚠️ 建议深度质检 |
| <50 | 危险 | ❌ 不建议上线 |

计分：阻断项1个扣15分，警告项1个扣5分。

## 附录A：Python项目快速自检（10项核心）

**适用**：Python后端、脚本、数据处理、爬虫等

```markdown
## ❌ 必过项（不过不能上线，阻断级）
- [ ] 1. 没有裸except，所有异常都有明确的捕获类型
  判断标准：搜 `except:` 和 `except Exception:`，都要有具体异常类型
- [ ] 2. 数据库连接在finally中关闭，或使用上下文管理器（with）
  判断标准：搜 `conn =` 或 `connect(`，后面有没有 close() 或 with
- [ ] 3. 没有硬编码的密钥、密码、Token（用环境变量或配置文件）
  判断标准：搜 `password`、`token`、`secret`、`key =`，值是不是写死的
- [ ] 4. 用户输入都做了校验（类型、长度、范围、格式）
  判断标准：接口入参、命令行参数、文件读取都有校验
- [ ] 5. 没有SQL字符串拼接，用参数化查询
  判断标准：搜 `"SELECT ... WHERE ..." +` 或 f-string 拼SQL，发现就是高危
- [ ] 6. 错误日志不泄露敏感信息（密码、Token、堆栈直接返回前端）
  判断标准：报错信息里有没有 password、token 等关键词

## ⚠️ 建议项（最好修一下，警告级）
- [ ] 7. 函数长度不超过50行，单个函数只做一件事
  判断标准：数行数，超过50行考虑拆分
- [ ] 8. 变量命名有意义，不用 a、b、temp、data1 这类模糊名
  判断标准：看变量名能不能猜出它存的是什么
- [ ] 9. 关键逻辑有注释说明"为什么这么做"（不是"做了什么"）
  判断标准：复杂逻辑段有没有解释原因的注释
- [ ] 10. 依赖版本锁定（requirements.txt 有具体版本号）
  判断标准：requirements.txt 里是 `flask==2.0.0` 还是只有 `flask`

## 📊 计分
  通过 = 每项得分 = 总分 / 10 × 100
  阻断项1个扣15分，警告项1个扣5分
```

## 附录B：前端项目快速自检（10项核心）

**适用**：Web前端、小程序、H5、React/Vue项目

```markdown
## ❌ 必过项（不过不能上线，阻断级）
- [ ] 1. 没有硬编码的API密钥、Token、Secret
  判断标准：搜 `apiKey`、`token`、`secret`、`.env` 之外的密钥
- [ ] 2. 用户输入都做了校验和转义（防XSS）
  判断标准：表单输入、URL参数、富文本内容都有转义或用安全API
- [ ] 3. 敏感操作有确认提示（删除、支付、修改密码等）
  判断标准：不可逆操作前有没有二次确认
- [ ] 4. API请求错误有友好提示，不会白屏或崩溃
  判断标准：网络错误、404、500时页面有没有提示
- [ ] 5. 表单有防重复提交机制
  判断标准：快速点两次提交按钮会不会发两次请求
- [ ] 6. 没有用 dangerouslySetInnerHTML 之类的危险API（或有严格防护）
  判断标准：搜 `dangerouslySetInnerHTML`、`v-html`、`innerHTML`

## ⚠️ 建议项（最好修一下，警告级）
- [ ] 7. 组件职责单一，单个组件不超过300行
  判断标准：数组件代码行数
- [ ] 8. 列表渲染有正确的 key，没有用 index 当 key
  判断标准：React 中 key 是不是用的唯一ID
- [ ] 9. 副作用有清理（定时器、事件监听、订阅）
  判断标准：useEffect/onMounted 里的定时器有没有清除
- [ ] 10. 图片有 alt 属性，重要图片有懒加载
  判断标准：<img> 标签有没有 alt，长列表图片有没有懒加载

## 📊 计分
  通过 = 每项得分 = 总分 / 10 × 100
  阻断项1个扣15分，警告项1个扣5分
```

## 附录C：扣子技能快速自检（10项核心）

**适用**：扣子/Coze 技能、Skill、插件、Agent能力

```markdown
## ❌ 必过项（不过不能上架，阻断级）
- [ ] 1. SKILL.md 格式正确，YAML头信息完整
  判断标准：name、description、version、trigger、category 都有
- [ ] 2. 描述清晰准确，不夸大、不误导
  判断标准：说能做到的是不是真能做到，有没有"最""第一"等极限词
- [ ] 3. 没有硬编码的密钥、密码、Token 等敏感信息
  判断标准：全文搜 password、token、secret、key 等关键词
- [ ] 4. 免费版/付费版边界明确，不欺诈
  判断标准：免费的标清楚，付费的也说清楚
- [ ] 5. 代码有基本的错误处理，异常输入不会崩溃
  判断标准：传空值、乱码、超长内容会不会报错
- [ ] 6. 不执行危险操作（删文件、改系统配置、外传数据等）
  判断标准：有没有 rm -rf、系统调用、数据外发等操作

## ⚠️ 建议项（最好有，警告级）
- [ ] 7. 有示例代码或使用示例
  判断标准：用户拿到手知不知道怎么用
- [ ] 8. 输出格式统一、易读
  判断标准：输出是不是乱的，有没有结构
- [ ] 9. 参数校验完善，边界情况有处理
  判断标准：空值、极值、特殊字符都处理了吗
- [ ] 10. 有明确的触发条件和使用说明
  判断标准：用户知不知道什么时候该用这个技能

## 📊 计分
  通过 = 每项得分 = 总分 / 10 × 100
  阻断项1个扣15分，警告项1个扣5分
```
